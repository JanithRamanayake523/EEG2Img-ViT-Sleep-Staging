# Notes: decisions, assumptions and issues found in the original notebooks

These matter for the paper because some of them can change reported numbers. Nothing in this code base has
been run yet, so none of the thesis results are reproduced or verified here.

## Things the original notebooks did that this code base changes

1. **Band-pass filter was a band-stop.** `raw.filter(l_freq=35, h_freq=0.5, ...)` has `l_freq > h_freq`, which
   MNE interprets as a *band-stop* between 0.5 and 35 Hz (it removes the EEG band and keeps drifts and
   high-frequency noise). Table 6.1 describes a 0.5-35 Hz band-pass. `data/edf_preprocess.py` implements the
   band-pass. Images generated by the old notebooks and by this code will therefore differ, and the accuracies
   may differ too. This is the first thing to check when re-running the experiments.
2. **Per-subject copy-pasted notebooks.** Channel names differ between recordings (`Fp1-F3`, `FP1-F3`, `F1-F3`,
   `F2-F4`) and some recordings miss `F7-T3`, `T3-T5`, `F8-T4`, `T4-T6`. The fix-ups are now one table in
   `constants.py` (`CHANNEL_ALIASES`, `CHANNEL_FALLBACKS`).
3. **Spectrogram sampling rate.** The spectrogram cell hard-coded `fs=256`; images are now computed with the true
   sampling rate of the (possibly resampled) signal.
4. **Resampling** (FFT/DWT) is not in any notebook. It is implemented in `data/resampling.py` and applied to the
   whole recording rather than epoch by epoch. The wavelet is not stated in the thesis; `db4` is an assumption
   (`preprocessing.dwt_wavelet`).
5. **`n3_resample.ipynb` is an empty file (0 bytes)**, so no resampling code existed to port.
6. **`Research/Temp/temp.ipynb` contains hard-coded numbers**, not measured results: the confusion matrix is
   labelled `# Define a dummy confusion matrix`, and the "real vs generated pixel histograms" are built from
   `np.full(...)` constants. If any thesis figure (e.g. Figure 7.9 or the GAN pixel histograms) was produced from
   those cells, it does not reflect model output. `evaluation/plots.py` draws every figure from real predictions
   and real image arrays, so regenerate those figures after running the experiments. The model bar charts in that
   notebook (78.1 / 85.1 ...) were typed in by hand as well.

## Methodology points to be aware of (they affect how results should be interpreted)

* **Epoch-level splits leak across neighbouring epochs.** The notebooks (`CreateDS.ipynb`) and thesis split
  epochs randomly. Adjacent 30 s epochs of the same night are highly correlated, so validation accuracy is
  optimistic compared with predicting sleep stages for an unseen person. `experiments.split_by: epoch` keeps the
  thesis protocol (default); set `experiments.split_by=subject` for a subject-wise split. Reporting both would
  strengthen the paper.
* **Table 7.8 (DS1-DS8) scores subsets of the data the model was trained on.** DS1-DS8 are subsets of DS9, which
  was used for training, so these numbers are not independent generalisation. `08_final_evaluation.py` reports
  `all_epochs` (thesis protocol) next to `held_out` (validation epochs only); true generalisation needs
  subject-wise hold-out.
* **Hypnogram alignment.** Scoring times in the `.txt` files are wall-clock times. EDF header start times are
  unreliable (e.g. `n2.edf` header 19:12 vs first score 22:19) and often earlier than the first scored epoch. The
  original notebooks assumed that the first scored epoch is the first epoch of the signal; that is the default
  here (`data.align: first_stage`). If that assumption is wrong for some subjects, labels are shifted by a few
  epochs. `data.align: edf_start` and `data.manual_offsets_epochs` are provided to test this.
* **Average channel.** The notebooks average the 15 raw channels (EEG, EOG, EMG, ECG, in mixed units) *before*
  filtering and then only notch-filter it. This is reproduced (`preprocessing.avg_before_filter: true`); the
  per-epoch min-max scaling inside each transform makes the unit mix less critical.
* **GAN-augmentation evaluation.** Experiment 6 trains the classifier on synthetic data and evaluates on real
  validation images. The DCGAN is trained only on the training split (Experiment 5) so validation images never
  influence the generator.
* **Up-sampling** (Experiment 3) is done *after* the split and only on the training part so duplicated epochs
  cannot appear in validation data.
* **Table 7.2** reports clustering scores of ViT embeddings; the notebooks computed them on the 2-D t-SNE map.
  Both variants are saved (`*_raw` keys are on the original feature space).
* **MPED / SSIM / FID** definitions are not fully specified in the thesis. Here: SSIM against the nearest real
  image, MPED as mean pairwise Euclidean distance of pixels scaled to [0, 1], FID with torchmetrics' Inception
  features. Absolute values will not match the thesis numbers (SSIM 0.83, FID 18.7, MPED 5.62) unless those used
  identical definitions.

## Choices made where the thesis is silent

| Item | Choice | Config key |
|---|---|---|
| Framework | PyTorch + timm (the notebooks mixed Keras and unspecified code for the pre-trained ViTs) | - |
| PVT-Small | `pvt_v2_b2` (PVT v1 small is not in recent timm) | `constants.PRETRAINED_MODELS` |
| Optimiser | AdamW, lr 1e-4, 10 epochs, early stopping on val accuracy, ReduceLROnPlateau on val loss (matches the notebooks' callbacks) | `classifier.*` |
| Scratch ViT positions | sinusoidal (Eq. 6.23-6.25); the Keras notebook used learned embeddings | `scratch_vit.pos_embed` |
| DCGAN training | Adam 2e-4, beta1 0.5, batch 32, 100 shared epochs then 500 per class; the notebook used 5,000 epochs on one class | `gan.*` |
| DCGAN output | Discriminator outputs logits (sigmoid is inside `BCEWithLogitsLoss`) | - |
| Mixed Exp. 6 set | 50 % original / 50 % synthetic per class | `augmentation.mixed_original_fraction` |
| 'Imbalanced' set (Exp. 3) | random sample of DS9 with natural stage proportions, same size as the balanced sample | `--n-total` |
| Recordings not at 512 Hz | those are excluded (as in Section 4.2); recordings with a different EEG rate are resampled to 512 Hz only if they are included manually | `data.required_fs` |
